# powerUp 採点ロジック専門レビューとv2＋推定設計

更新日：2026-07-30

## 1. 目的

powerUpは、睡眠・食事・デジタル環境が本人のパフォーマンスとどう関係するかを振り返るためのアプリである。医学的診断、血糖評価、脳内ドーパミン量の推定には使用しない。

旧v1は、睡眠50・食事30・スマートフォン10・成果10を合算していた。この方式では、パフォーマンスの原因候補と結果を同じ点数へ足すため、成果を出していない日でも生活行動だけで高得点になり得る。また、睡眠点を総合点へ含めた状態で睡眠と総合点の関係を分析すると、定義上の循環が生じる。

## 2. 専門エージェントレビュー

| レビュー領域 | 主な結論 |
|---|---|
| 睡眠 | 睡眠50点は過大。ウェアラブルの睡眠スコアはパフォーマンス百分率ではない。回復感は小さな補正として扱う |
| 生産性 | 成果・集中・品質評価をパフォーマンス総合点とし、睡眠・食事・スマホは説明変数として分離する |
| 食事・栄養・血糖 | 食事30点は入力精度に対して過大。20点の食事行動指標とし、血糖値を測定したかのような表現をしない |
| ドーパミン・行動科学 | スマホ利用からドーパミン量は評価できない。通知・中断・時間の置換を扱う8点のデジタル注意環境指標とする |

4レビューを統合し、単一の「健康行動＋成果」スコアを廃止する。v2では、パフォーマンス結果と、その条件になり得る指標を分離する。

## 3. v2のスコア構造

画面で扱う採点系統は次の5種類である。

1. 実際のパフォーマンス
2. 睡眠コンディション
3. 食事行動
4. デジタル注意環境
5. 推定パフォーマンス

コード上は、上記を構成する公開計算関数が13個ある。うち実際のパフォーマンスと推定パフォーマンスは別の計算経路であり、互いの保存値を上書きしない。

### 3.1 パフォーマンススコア：100点

| 指標 | 配点 | 計算 |
|---|---:|---|
| 確定成果 | 55 | `confirmedAchievementScore / 5 × 55` |
| 集中作業 | 30 | `min(focusMinutes, 90) / 90 × 30` |
| 成果の品質・効率 | 15 | `(reflectionRating - 1) / 4 × 15` |
| 合計 | 100 | 各点を合算 |

成果点はGeminiの提案をそのまま確定値にせず、ユーザーが0〜5で確定する。集中時間は投入量であって成果そのものではないため、90分で上限とする。品質・効率は成果量と同じ意味にならないよう、UI上の「今日の手応え」から名称を変更する。

未入力項目は0点や推定値へ変換しない。入力済み項目の獲得点を固定100点スケール上で表示し、次の配点カバー率を併記する。

```text
performanceTotal = achievementPoints + focusPoints + qualityPoints
performanceCoverage = 入力済み項目の配点合計 / 100 × 100
```

例：成果点だけ5/5で確定した場合は、55/100、カバー率55%、暫定表示となる。睡眠・食事・デジタル環境を変更しても、同じ成果入力のパフォーマンス点は変化しない。

### 3.2 睡眠コンディション：30点

```text
subjectiveIndex =
  回復感あり: (recoveryFeeling - 1) × 25
  回復感なし: pixelWatchScore

combinedSleepIndex =
  pixelWatchScore × 0.85
  + subjectiveIndex × 0.15

sleepCondition = round(combinedSleepIndex × 0.30)
```

Pixel Watchスコアが未入力なら、回復感だけで睡眠点を作らず`null`とする。回復感未入力時は、Pixel Watchスコアのみで計算し、未入力ペナルティを付けない。睡眠点はパフォーマンス総合点へ加算しない。

### 3.3 食事行動：20点

| 指標 | 配点 |
|---|---:|
| 3食の構成・量・飲料 | 15 |
| 食後歩行 | 2 |
| 食事タイミング | 2 |
| 間食 | 1 |

各食事の構成は5点とする。

| 入力 | 配点 |
|---|---:|
| 野菜 | 十分1.5、少量0.75、なし0 |
| たんぱく質 | 十分1、少量0.5、なし0 |
| 量 | 適量1、やや多い0.5、食べ過ぎ0 |
| 飲料 | 水・お茶／無糖1、甘い飲料0 |
| 炭水化物量 | 多い・主食の重ね食い0、それ以外0.5 |

`noodle`、`fried`、`eating-out`は、それだけでは点数を変更しない。食後歩行は0〜10分を連続的に評価し、3食合計で最大2点とする。食後の眠気は原因を特定できないため、食事点へ加算・減点しない。

この指標は一般的な食事行動の振り返りであり、血糖値、血糖スパイク、糖尿病リスク、インスリン抵抗性を評価しない。

### 3.4 デジタル注意環境：8点

| 入力 | 配点 |
|---|---:|
| 娯楽利用時間 | 120分以下3、180分以下2、240分以下1、240分超0 |
| 作業中の通知・確認行動を抑えた | 3 |
| 朝夜の利用境界を守った | 2 |

3入力のいずれかが未入力なら、時間を推定せずカテゴリ全体を`null`とする。120・180・240分は医学的基準ではなく、MVPの暫定バンドである。将来は総時間より、通知回数、短時間の反復確認、集中モード利用などを優先する。

「ドーパミンデトックス」「脳内ドーパミンをリセット」といった説明は使用しない。扱うのは注意中断、睡眠機会、活動時間の置換、確認習慣の手掛かりである。

### 3.5 現在時点の推定パフォーマンス：100点

評価時刻における「今の状況」を説明可能な決定ルールで表す。日次平均、実績値、医学的予測、因果推定ではない。固定的に「午後は低い」と扱わず、起床後時間、直近の食事、連続作業、次の予定までの余白によって同じ日の中の変化を表す。

| 計算要素 | 重み |
|---|---:|
| 睡眠準備度（Pixel Watch 75%、朝の回復感25%） | 30 |
| 起床後経過時間 | 10 |
| 現在の覚醒感 | 15 |
| 連続作業・次の予定までの余白 | 10 |
| 直近4時間の食後状態・直近3時間の間食 | 20 |
| 現在のデジタル注意環境 | 15 |

各要素の素点を`S`、その要素内の入力カバー率を`q`、重みを`w`とする。欠測部分は0点にも平均値の代入にもせず、中立値50へ縮約する。

```text
要素の補正値 = 50 + q × (S - 50)

estimatedPerformance =
  round(Σ(w × 要素の補正値) / 100)

estimateCoverage =
  round(Σ(w × q))
```

入力済み要素だけで100点へ再正規化しない。カバー率0〜34%は数値を隠して「情報不足」、35〜59%は「推定・低カバー率」、60〜79%は「推定・中カバー率」、80%以上は「推定・高カバー率」と表示する。

#### 睡眠・日内変動

- Pixel Watchは睡眠準備度内で75%、朝の回復感は25%
- 起床後0分55、30分75、60分90、2〜10時間100、14時間85、17時間55、20時間30を線形補間
- 現在の覚醒感1〜5を20〜100へ変換
- 連続作業は60分まで100、90分85、120分70、以後は緩やかに50まで低下
- 次の予定まで90分以上100、60分85、30分65、15分40、直前20

#### 食事・間食

- 現在以前かつ直近4時間の食事だけを対象にし、0〜30分で効果が立ち上がり、30〜120分を最大、120〜240分で減衰させる
- 食後眠気1〜5があれば本人の直接反応として最優先し、同じ食事の量・主食・飲料・特徴・歩行は重ねて計算しない
- 食後眠気が未記録の場合だけ、量、主食量、たんぱく質、野菜、甘い飲料、揚げ物、食後歩行を弱い代理情報に使う
- 麺類と外食は種類だけで減点しない。主食の重ね食いは主食量「多い」と二重減点しない
- 間食は直近3時間だけ弱く反映し、「間食なし」は加点せず中立
- 食事時刻の乱れ、就寝直前の夕食、長い空腹後の食べ過ぎは、現在推定へ各±1点の弱い補助情報として反映

#### デジタル注意環境

3項目をすべて必須にせず、入力済み項目を個別に採点する。内部ウェイトは作業中の通知・確認60%、現時点までの娯楽利用25%、朝夜の利用境界15%。通知を抑えられなかった場合も能力0点とはせず60点とし、注意中断の手掛かりとして扱う。

- 条件入力が1つもなければ推定値は`null`
- 実績パフォーマンスは別カードに常時表示し、推定と切り替えない
- 推定値は`total_score`、`result_score`、実績の7日平均・時系列へ含めない
- 推定モデル版は`current-condition-v2`として実績の採点版`v2`と別管理する

### 3.6 入力フォームの運用

- 成果点と品質・効率には、数値だけでなく0・3・5または1・3・5の判断基準を表示する
- 集中作業時間は実時間を保存し、採点上限が90分であることを入力欄へ明記する
- 食事タイミング、間食の就寝前、デジタル注意環境は「できた／できなかった／未記録」を区別する
- 間食の量と就寝前を別入力にし、`beforeBed`を明示的に保存する
- 食後眠気は現在推定で優先し、未記録時だけ食事の量・構成・飲料・揚げ物・歩行を弱く使うことを表示する
- 麺類・外食は種類だけで減点しないことを表示する
- 評価時刻、起床時刻、現在の覚醒感、連続作業、次の予定までを推定専用入力として表示する

## 4. 欠測とデータ移行

- `null`を0や平均値へ変換しない
- 部分入力を満点へ再正規化しない
- パフォーマンスのカバー率は、成果55・集中30・品質15の入力済み配点で計算する
- 現在推定の欠測部分は中立値50へ縮約し、入力済み条件だけで100点へ再配分しない
- v1の保存データは、読み込み時にv2の採点関数で再計算する
- 新規保存時の`scoreVersion`は`v2`とする
- 旧スコアとの時系列比較では、バージョン境界を明示する

## 5. 解釈上の制約

- スコアは本人内の振り返り用であり、他人との順位付けには使わない
- 睡眠ウェアラブルは睡眠障害の診断や治療判断に使わない
- 食事入力から血糖値や疾病リスクを推定しない
- スマホ時間から脳内ドーパミン量や依存症を判定しない
- 4〜8週間以上の本人データを蓄積してから、条件指標とパフォーマンスの関連を探索する
- 関連が見えても因果関係とは断定しない
