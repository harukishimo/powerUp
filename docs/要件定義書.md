# powerUp 要件定義書

## 1. 文書概要

| 項目 | 内容 |
|---|---|
| プロダクト名 | powerUp（仮） |
| 文書種別 | MVP要件定義書 |
| ステータス | Draft v0.2 |
| 作成日 | 2026-07-29 |
| 対象 | 一日の生産性を高めたい個人ユーザー |

本書は、睡眠・食事・スマートフォン利用・実際の成果を記録し、ユーザー自身の生産性が高まりやすい条件を発見するアプリの初期要件を定義する。

### 1.1 実装前提

- フロントエンドと画面ルーティングはNext.jsを使用する
- データベースは使用せず、Google SpreadsheetをMVPの記録保管先とする
- AIはGoogle Gemini APIを使用し、APIキーをブラウザへ公開しない
- デプロイ先はVercelとする
- MVPは個人利用または少人数の非公開利用を前提とし、一般公開時は認証・アクセス制御を追加する

## 2. プロダクトの目的

### 2.1 解決したい課題

ユーザーは、生産性が低い日の原因を感覚だけで判断している。睡眠不足、食後の眠気、間食、スマートフォンの使い過ぎなどの行動と、実際の集中・成果との関係を簡単に記録して振り返れる仕組みが必要である。

### 2.2 プロダクトビジョン

「生産性を測るアプリ」ではなく、「自分の生産性が上がる条件を発見するアプリ」を目指す。

アプリはユーザーを一律に採点するのではなく、初期の一般的な基準と、蓄積された本人のデータを組み合わせて、次の日に実行しやすい改善提案を1つだけ提示する。

### 2.3 MVPの成功条件

- 1日の入力を2分程度で完了できる
- 睡眠・食事・スマートフォン利用・成果の記録が1画面または少ない操作で完了する
- 日次スコアと7日間の傾向が確認できる
- ユーザーが「何を変えると自分の集中や成果が変わるか」を発見できる
- AIの採点結果をユーザーが確認・修正できる

## 3. 想定ユーザー

### 3.1 主なユーザー

- 会社員、学生、個人事業主など、日々の集中力を高めたい人
- Google Pixel WatchまたはFitbitを利用している人
- 厳密なカロリー計算やタスク管理より、軽い記録と振り返りを好む人

### 3.2 想定しない用途

- 医療上の睡眠・食事診断
- 糖尿病などの疾病管理
- ダイエットのための厳格なカロリー制限
- チーム向けの勤怠・業績管理

## 4. 基本コンセプト

### 4.1 入力方針

入力は、数値を細かく入力する方式ではなく、選択式チェックリストと短い自然文を中心とする。

- 睡眠：Pixel Watchの睡眠スコアを手入力する
- 食事：主食・たんぱく質・野菜・量・飲料・間食などを選択する
- スマートフォン：利用時間と利用状況を記録する
- 成果：その日に実際に進んだこと、集中時間、短い振り返りを入力する

朝に「今日やるタスク」を登録することはMVPの必須機能としない。

### 4.2 AIの役割

MVPのAIプロバイダーはGoogle Gemini APIを使用する。無料枠を利用して試作し、利用量・レート制限・データ利用条件を確認した上で、必要に応じて有料枠またはローカルAIへ切り替えられる構成にする。Gemini APIへのリクエストはNext.jsのサーバー側処理から実行する。

AIは、入力をもとに以下を自動で行う。

- 食事内容や短いコメントの分類
- 各項目の採点案の作成
- 日次コメントの要約
- 過去データからの本人向け傾向分析
- 翌日に試す改善案の提示

AIの採点は確定値ではなく「AIの提案」とし、ユーザーが修正または確定できる。AIの出力だけで医療的な判断を行わない。

## 5. スコア体系

現行のv2では、「パフォーマンス結果」と「その条件になり得る生活指標」を分離する。詳細な専門レビュー、根拠、計算式は[`採点ロジックレビュー.md`](./採点ロジックレビュー.md)をソース・オブ・トゥルースとする。

| 指標 | 満点 | 総合点への扱い |
|---|---:|---|
| パフォーマンス | 100点 | 成果55・集中30・品質/効率15を合算 |
| 睡眠コンディション | 30点 | 独立指標。総合点へ加算しない |
| 食事行動 | 20点 | 独立指標。総合点へ加算しない |
| デジタル注意環境 | 8点 | 独立指標。総合点へ加算しない |

これにより、睡眠・食事・デジタル環境とパフォーマンスの関係を、定義上の循環を起こさずに分析する。

### 5.1 旧v1総合スコア（廃止）

以下の5.1〜5.5は初期設計の履歴として残す。実装には使用しない。

### 5.2 旧v1睡眠スコア：50点（廃止）

ユーザーがGoogle Pixel Watchの睡眠スコアを0〜100で入力する。

```text
睡眠ポイント = Pixel Watch睡眠スコア × 0.5
```

例：Pixel Watchの睡眠スコアが82点の場合、睡眠ポイントは41点。

Pixel Watchの睡眠スコアには睡眠時間など複数の指標が含まれるため、MVPでは睡眠時間を別途加点して二重評価しない。

任意入力として「朝の回復感」を1〜5で記録できるようにする。回復感は睡眠スコアに加算せず、本人の感覚とデバイススコアの差を分析するために利用する。

睡眠スコアが取得できなかった場合は0点にせず、「未記録」とする。総合スコアでは未記録項目を除外し、記録率を別途表示する。

### 5.3 旧v1食事スコア：30点（廃止）

朝食・昼食・夕食をそれぞれ個別に記録・採点し、間食も独立した項目として評価する。食事ごとの違いを残すことで、昼食後の眠気や夕食後の睡眠との関係を分析できるようにする。

料理名を一律に善悪判定しない。ラーメンなども、主食の重なり、たんぱく質、野菜、量、飲料、スープ摂取などの要素で評価する。

| 項目 | 配点 | 入力例 |
|---|---:|---|
| 朝食 | 8点 | バランス・量・内容・食後歩行 |
| 昼食 | 8点 | バランス・量・内容・食後歩行 |
| 夕食 | 8点 | バランス・量・内容・食後歩行 |
| 食事の時間帯 | 3点 | 食事の規則性、就寝直前の食事の有無 |
| 間食 | 3点 | 内容、量、計画性、時間帯 |
| 合計 | 30点 |  |

#### 食事ごとの配点

朝食・昼食・夕食は、それぞれ以下の8点満点で採点する。

| 項目 | 配点 | 判定例 |
|---|---:|---|
| 主食・たんぱく質・野菜のバランス | 3点 | 3項目がそろっているか |
| 食べる量 | 2点 | ちょうどよい、やや多い、食べ過ぎ |
| 食事内容・飲料 | 2点 | 甘い飲料、揚げ物中心、主食の重ね食いなど |
| 食後の歩行 | 1点 | 10〜15分程度の歩行など |
| 合計 | 8点 |  |

バランスは、主食・たんぱく質・野菜を各1点として採点する。少量の場合は0.5点としてもよいが、MVPでは入力を簡単にするため、まずは「十分・少量・なし」の3択を基本とする。

#### 食事入力の例

```text
食事：朝食／昼食／夕食
食事時刻： [時刻を入力]

主食       [十分] [少量] [なし] [多い]
たんぱく質 [十分] [少量] [なし]
野菜       [十分] [少量] [なし]
食事量     [ちょうどよい] [やや多い] [食べ過ぎ]
飲み物     [水・お茶] [無糖飲料] [甘い飲料]
料理の特徴 [通常] [麺類] [揚げ物] [外食] [主食の重ね食い]
食後歩行   [10分以上] [5分程度] [なし]
```

#### 食事の時間帯

食事の時間帯は、個々の食事時刻を記録した上で、1日3点として評価する。

- 食事時刻が大きく乱れていない：1点
- 夕食が就寝直前になっていない：1点
- 長時間の空腹後に大量の食事をしていない：1点

固定の時刻だけで判定せず、ユーザーの起床時刻・就寝時刻・勤務形態を考慮できる設計にする。シフト勤務などの場合は、初期設定で生活パターンを選択できるようにする。

#### 間食の配点

間食は発生の有無だけでなく、内容・量・時間帯・計画性を評価する。間食がない場合は中立の3点とし、間食を推奨する点数設計にはしない。

| 間食の状態 | 点数 |
|---|---:|
| 間食なし、または少量で計画的な間食 | 3点 |
| おにぎり、卵、乳製品、無塩ナッツ、無糖ヨーグルト、果物など | 2〜3点 |
| 菓子や甘い飲料のみ、または量がやや多い | 1点 |
| 大量の間食、連続した間食、就寝直前の間食 | 0点 |

間食が複数回ある場合は、各間食の平均を1日の間食スコアとし、最大3点に制限する。

間食の「あり・なし」は記録し、食後の眠気や翌日の集中時間との関係を分析する。

#### 食後の眠気

食後の眠気は食事スコアに直接組み込まず、結果指標として別に記録する。

```text
食後の眠気：1〜5
```

これにより、「野菜とたんぱく質を取った日」「食後に歩いた日」「甘い飲料を飲んだ日」などの本人の傾向を分析できる。

### 5.4 旧v1スマートフォン利用スコア：10点（廃止）

| 項目 | 配点 | 入力・取得方法 |
|---|---:|---|
| 娯楽利用時間 | 5点 | その日の目標時間との比較 |
| 作業中の分離 | 2点 | 通知オフ、別室、集中モードなど |
| 起床後の利用 | 1点 | 起床後30分以内の娯楽利用 |
| 就寝前の利用 | 2点 | 就寝前の画面利用、寝室への持ち込み |
| 合計 | 10点 |  |

スマートフォンの使用時間は、可能であればOSのスクリーンタイム等から取得し、MVPでは手入力にも対応する。

### 5.5 旧v1実際の成果スコア：10点（廃止）

朝のタスク登録は行わず、夜に「今日実際に進んだこと」を記録する。

| 項目 | 配点 | 算出方法 |
|---|---:|---|
| 実際の成果 | 5点 | AIがコメントから成果の具体性・重要性・完了度を評価 |
| 集中作業時間 | 3点 | 0分、30分、60分、90分以上を段階評価 |
| 振り返り | 2点 | 1〜5の手応えを0〜2点へ変換 |
| 合計 | 10点 |  |

#### 実際の成果

ユーザーは、1〜2文でその日に進んだことを入力する。

```text
例：企画書の構成を完成させ、上司にレビュー依頼を送った。
```

AIは以下の観点で0〜5点の採点案を作る。

- 具体的な成果物や完了事項があるか
- 重要な前進があるか
- 単なる作業時間ではなく、結果につながっているか
- ユーザー自身が入力した達成度と矛盾していないか

ユーザーが「今日の成果は特になし」と入力した場合も、低評価を押し付けず、0〜2点程度の提案にとどめる。AIの点数はユーザーが修正できる。

#### 集中作業時間

MVPの初期基準は以下とする。

| 集中時間 | 点数 |
|---:|---:|
| 0〜29分 | 0点 |
| 30〜59分 | 1点 |
| 60〜89分 | 2点 |
| 90分以上 | 3点 |

将来的には、ユーザーの過去14日間の中央値を基準にして個人化する。ただし、長時間労働を促さないため、3点を上限とする。

#### 振り返り

入力は1〜5の5段階とする。

```text
今日の手応え
1：ほとんど進まなかった
2：少し進んだ
3：普通
4：かなり進んだ
5：非常に良かった
```

点数への変換は以下とする。

```text
1〜2 → 0点
3    → 1点
4〜5 → 2点
```

コメントは任意入力とし、1〜2文程度に制限する。コメントは点数に直接加算せず、AIによる原因分析・翌日の提案に利用する。

## 6. 主要ユーザーフロー

### 6.1 朝

1. Pixel Watchの睡眠スコアを入力
2. 任意で朝の回復感を入力
3. 前日の総合スコアと7日間の傾向を確認

### 6.2 食事時

1. 朝食・昼食・夕食・間食のいずれかを選択
2. 食事時刻を記録
3. 主食・たんぱく質・野菜・量・飲料を入力
4. 必要に応じて食後の歩行を記録
5. 食後の眠気を1〜5で入力

### 6.3 夜

1. 実際に進んだことを1〜2文で入力
2. 集中作業時間を入力
3. 1日の手応えを1〜5で入力
4. 任意で短いコメントを入力
5. AIが各項目の採点案と改善提案を表示
6. ユーザーが採点を確認・修正
7. 日次スコアを確定

## 7. 画面要件

### 7.1 今日の画面

- 今日の総合スコア
- 睡眠・食事・スマホ・成果の内訳
- 未入力項目
- 今日の改善提案1つ
- 前日比・7日平均

### 7.2 記録画面

- 睡眠記録
- 食事記録
- 間食記録
- スマートフォン利用記録
- 成果・集中時間・振り返り記録

### 7.3 分析画面

- 7日・30日のスコア推移
- 食後の眠気と食事内容の関係
- 集中時間と睡眠スコアの関係
- スマートフォン利用時間と成果の関係
- 本人向けの傾向コメント

### 7.4 デイリーログ振り返り画面

- 直近7日間の日付を選択できる
- 日ごとの総合スコアと4カテゴリの内訳を確認できる
- 睡眠・食事・スマートフォン・成果の記録内容を確認できる
- ユーザーコメント、AIの気づき、当日のタイムラインを確認できる
- 未入力項目は「未記録」と表示し、0点と混同させない

### 7.5 14日間集中リセット画面

- PC版YouTube対策を中心としたDay1〜Day14の課題を表示する
- 今日の行動、Unhook・StayFocusd・ブラウザProfileなどの環境設定をチェックできる
- YouTubeを開く前の目的を1行で記録できる
- 欲求の直前に起きたことと、「開かなかった・閉じて戻った・視聴した」の結果を記録できる
- 無目的起動回数、仕事中視聴時間、Shorts時間、仕事開始までの時間をDay1と比較できる
- 視聴を記録した場合も失敗と断定せず、次の復帰行動を提示する
- 5分開始ルールを実行するための簡易タイマーを表示する

## 8. AI要件

### 8.1 AI採点

- AIプロバイダーはGoogle Gemini APIを使用する
- 入力された選択肢と自然文から採点案を生成する
- 採点理由を短く表示する
- 点数の根拠が曖昧な場合は低信頼として表示する
- ユーザーが点数を修正できる
- 修正内容を次回以降の個人設定に反映する
- APIキーはフロントエンドに埋め込まず、バックエンドの環境変数で管理する
- 総合スコアの数値計算はプログラムで行い、Geminiは分類・理由説明・提案を担当する

### 8.2 AI提案

改善提案は一度に1つだけ表示する。

例：

```text
昨日は昼食後の眠気が強めでした。
次回は甘い飲料を無糖のお茶に替えてみましょう。
```

### 8.3 禁止事項

- 疾病の診断や治療判断を行わない
- 「この食事は悪い」と断定しない
- 睡眠スコアだけで健康状態を断定しない
- AIの採点をユーザーの修正なしに確定しない

## 9. データ要件

### 9.1 日次記録

- 日付
- 睡眠スコア
- 朝の回復感
- 朝食の記録・時刻・食事スコア
- 昼食の記録・時刻・食事スコア
- 夕食の記録・時刻・食事スコア
- 食事の時間帯スコア
- 間食記録一覧・時刻・間食スコア
- 食後の眠気
- 食後の歩行
- スマートフォン利用時間
- 実際の成果コメント
- 集中作業時間
- 振り返り評価
- ユーザーコメント
- AI採点案
- ユーザー確定点
- 採点ルールのバージョン

### 9.2 記録状態

各項目は以下の状態を持つ。

- 未入力
- AI仮採点
- ユーザー確認済み
- ユーザー修正済み

未入力を0点として扱わない。スコアとともに「記録率」を表示する。

### 9.3 保存先の前提

MVPではGoogle Spreadsheetを唯一の保存先とし、アプリ専用のデータベースは持たない。日次記録、食事、間食、AI提案はスプレッドシートのタブを分けて管理する。保存処理はサーバー側からGoogle Sheets APIを呼び出す。

スプレッドシートはユーザーの健康・生活データを含むため、一般公開URLで共有しない。個人利用では専用シートを利用し、少人数利用へ拡張する場合はユーザーごとの認証・アクセス範囲を追加する。

## 10. 非機能要件

- 食事1回の入力は30秒以内を目標とする
- 睡眠入力は10秒以内を目標とする
- 1日の必須入力は2分以内を目標とする
- スコア計算結果は同じ入力に対して再現可能である
- AIの採点理由を確認できる
- 個人の健康データを第三者に公開しない
- データの削除・エクスポートができる
- 日次スコアを過度な自己管理や睡眠不足の助長に使わない

## 11. MVPの対象外

- Pixel Watchからの自動同期
- 食事写真のAI解析
- バーコードによる食品データ取得
- 血糖値・CGMとの連携
- 医師や管理栄養士への共有
- SNS、ランキング、他ユーザーとの比較
- 朝のタスク管理

## 12. リスクと対策

| リスク | 対策 |
|---|---|
| 入力が面倒で続かない | 選択式中心、自由記述は任意、入力時間を短くする |
| AIが食事を誤判定する | 採点理由を表示し、ユーザー修正を可能にする |
| ラーメン等を一律に悪と判定する | 料理名ではなく構成・量・組み合わせで評価する |
| 未入力が低得点になる | 未入力と0点を分ける |
| 点数を上げるために働き過ぎる | 集中時間の点数に上限を設定する |
| 睡眠スコアを医療判断に使う | 健康指標ではなく本人の振り返り指標と明示する |
| 1日の変動に振り回される | 7日平均・30日傾向を中心に表示する |
| Google Spreadsheetの同時編集や行ずれ | 日付・食事区分をキーにした更新、保存前の入力検証、変更履歴の確認を行う |
| APIキーや個人データの漏えい | GeminiとSheetsの呼び出しをサーバー側に限定し、Vercel環境変数で秘密情報を管理する |

- Gemini API無料枠で使用する具体的なモデル、レート制限、データ利用条件の最終確認
- 個人利用のまま運用するか、複数ユーザー向け認証を追加するか
- 一般公開時の認証方式と個人情報保護方針
- 食事スコアの初期配点を固定するか、ユーザーが変更できるようにするか
- 睡眠・食事・スマホ・成果の配点を将来個人化するか

## 14. MVP受け入れ条件

- ユーザーが睡眠スコアと回復感を入力し、30点の独立指標として確認できる
- 朝食・昼食・夕食をそれぞれ個別に記録し、各5点で採点できる
- 食事時刻を記録し、1日2点の時間帯スコアを算出できる
- 間食の有無・内容・量・時刻を記録し、1日1点で採点できる
- 甘い飲料、食べ過ぎ、遅い食事、食後歩行を記録できる
- 集中作業時間を入力し、0〜30点で連続的に計算できる
- 実際の成果コメントからAIが0〜5点の採点案を出せる
- 成果の品質・効率を0〜15点に変換できる
- AI採点をユーザーが修正できる
- 成果55・集中30・品質15による100点満点のパフォーマンススコアを表示できる
- 7日間の平均・推移を確認できる
- 過去7日分のデイリーログを選択し、日ごとの内訳・コメント・AIの気づきを確認できる
- 未入力と0点が区別される
- 入力内容から翌日の改善提案を1つ表示できる

## 15. 現行スコアのまとめ

```text
パフォーマンス100 = 確定成果55 + 集中作業30 + 成果の品質・効率15

独立指標:
睡眠コンディション30
食事行動20
デジタル注意環境8
```

v2では、睡眠・食事・デジタル環境をパフォーマンス点へ加算しない。4〜8週間分のデータが溜まった後に、本人内で各条件とパフォーマンスの関連を探索する。AIは配点を変更せず、採点案と翌日の実験提案だけを担当する。
